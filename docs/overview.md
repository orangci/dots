# Overview
How this flake is put together, so future me (or a brave stranger) doesn't have to reverse engineer it.

## Layout
- `flake.nix` ~ inputs, `flakeSettings`, and the code that builds a `nixosConfiguration` for every directory in `hosts/`.
- `hosts/HOSTNAME/` ~ one directory per machine.
    - `config.nix` is where modules get enabled.
    - `hardware.nix` is generated by `nixos-generate-config`.
    - `users.nix` lists the users. Exactly one of them gets `sysadmin = true`: that user owns the flake checkout, runs syncthing and is the admin of the homelab services. Modules get it as the `sysadmin` argument.
    - `homes/USERNAME.nix` is that user's home-manager config.
- `modules/` ~ NixOS (system) modules. Everything lives under `modules.*`.
- `home/` ~ home-manager modules. Everything lives under `hmModules.*`.
- `lib/` ~ my own helper functions, available as `lib.my.*`.
- `pkgs/` ~ packages exposed by the flake (the docs site, mudaremote).
- `secrets/` ~ the sops-encrypted `secrets.yaml`. See [secrets](./secrets.md).
- `assets/` ~ random files that don't belong anywhere else (browser extension settings, wallpapers and such).

## Hosts
- **komashi** ~ my desktop. Hyprland, gaming, all the usual.
- **gensokyo** ~ the homelab. Almost everything under `modules.services` runs here. See [server modules](./server.md).

Both are installed the same way, see [installation](./installation.md).

## How modules get loaded
Every host imports `lib.my.recursivelyImport [ ../../modules ]`, which pulls in **every** `.nix` file under `modules/` (except `example.nix` files). Home-manager does the same with `home/`.

That means importing a module does nothing by itself: each module declares an `enable` option and only does anything when it's switched on. Adding a file is enough for it to exist, you never need to touch an imports list. See [adding modules](./adding-modules.md).

## Using my modules in your flake
Every module is also a flake output: `nixosModules` for `modules/` and `homeModules` for `home/`, named after their option path. `modules/services/media/immich.nix` is `nixosModules."services.media.immich"`, and `home/cli/git.nix` is `homeModules."cli.git"`. `default` pulls in all of them.

```nix
modules = [ inputs.dots.nixosModules."services.tools.it-tools" ];
```

The exports bring their own `lib.my`, `flakeSettings` (mine, so your domains won't be in there) and `inputs`. Modules that lean on others, such as `security.sops` for secrets, need those exported too, or just use `default`. The `host`, `users` and `sysadmin` arguments only make sense on my own hosts, so modules that want `sysadmin` will throw elsewhere.

## flakeSettings
A small attrset in `flake.nix` that gets passed to everything as `flakeSettings`: the username, and my domains (`primary`, `secondary`, `email`, `tailnet`). Use it instead of hardcoding domains. (I do want to get rid of it eventually, it's in the [TODO](../TODO.md).)

## Helpers in lib.my
- `mkServerModule` ~ generates the options every homelab service has (port, subdomain, cloudflared, and so on). See [server modules](./server.md).
- `mkCaddyEntry` / `mkCloudflaredIngress` ~ for hooking a service into Caddy/Cloudflare Tunnel by hand.
- `recursivelyImport` ~ the importer described above.
- `hyprlandLua` ~ generates Hyprland's lua config.

## Pre-commit
The hooks in `.pre-commit-config.yaml` run `nixfmt`, `statix fix` and `deadnix`. If a commit fails, the hooks have probably just reformatted something, so stage it and try again.

## Docs site
The documentation page is built with [ndg](https://github.com/feel-co/ndg) in `pkgs/docs`. It renders the README, these docs and the options of every module. Build it with `nix build .#docs`.
